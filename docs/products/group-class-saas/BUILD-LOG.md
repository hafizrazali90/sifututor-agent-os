### 2026-07-06 (onboarding spotlight tour — 6 post-deploy hotfixes on `main`)

The M8 spotlight tour (merged via PR #10, `87322e2`) shipped with real bugs only visible once live traffic hit it. Hafiz caught each one from production screenshots and pushed back until the root cause was actually understood, not just papered over. All six on `main`, TDD + browser-verified each time:

- **`defd218`** — spotlighted buttons were unclickable. Onborda's `interact` prop defaults to `false`, which renders a full-viewport blocking div even over the highlighted target itself (confirmed via `document.elementFromPoint()`). Fixed by passing `interact` on `<Onborda>`.
- **`bf2afd1`** — every operator page's vertical spacing broke project-wide. Onborda wraps `children` in its own non-flex `relative w-full` / `block w-full` divs, which sat between `OnboardingTourProvider` and `DashboardLayout`'s `flex flex-col gap-4` container, silently zeroing the gap. Fixed by re-establishing the same flex+gap wrapper inside the provider.
- **`b3bb980`** — the highlight ring visually clashed with the target button's own border, and the connector arrow's color was wrong. Tightened `pointerPadding`/`pointerRadius` and recolored the arrow.
- **`5b2901e`** — the arrow's *position* was permanently wrong regardless of color (Hafiz: "I was asking the arrow position!" after an initial color-only misdiagnosis). Traced via `getBoundingClientRect()` + full ancestor/`offsetParent` chain to Framer Motion's animated `transform` on an ancestor div, which establishes its own CSS containing block independent of where the card visually renders — a library-internal bug, not fixable from app code. Hafiz's call: remove the arrow entirely rather than chase it upstream; the highlight ring alone says "look here."
- **`58efbce`** — added E2E coverage for the tour clickthrough regression (`tests/e2e/t2/onboarding-tour.t2.e2e.ts` now asserts the card's bounding box stays inside the viewport for all 5 tours, and checks `elementFromPoint` on the spotlighted target, not just that tour text exists).
- **`f1c2d87`** — tours persisted across navigation with a garbled highlight: "From billing to teacher pay to business, the highlighted looks so wrong." Root cause: `OnboardingTourProvider` wraps the whole operator layout and never unmounts between page navigations, so a tour started on Billing kept trying to re-target its old selector against whatever occupied that DOM position on Teacher Pay / Business. Fixed with a new `OnboardingTourRouteReset` component (sibling of `<Onborda>`, watches `usePathname()`, calls `closeOnborda()` on real path change). Verified live: Billing (tour visible, fresh org) → Teacher pay → Business, confirmed clean via DOM query and screenshot on both.
